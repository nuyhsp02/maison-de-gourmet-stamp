# V1.3 배포 전 반드시 확인할 문제

이번 작업은 트리 디자인·실기기 준비를 포함한 로컬 소스 수정과 자동 검증까지입니다.

기기별 상세 절차와 결과 기록은 MOBILE_TEST_GUIDE.md, 디자인 반영 설명은 DESIGN_NOTES.md를 참조하세요. 기존 event.json은 수정하지 않고 브랜드/그림을 표시 계층에 분리했습니다. STAMP_ART_GUIDE.md에 신규 SVG 파일과 교체 규격이 있습니다. 테스트 준비 도구의 임시 설정은 실제 행사 일정이 아닙니다. 운영 배포, 운영 DB 초기화, 도메인·방화벽 변경을 수행하지 않았습니다.

## 운영 개시 전에 결정할 것

- [ ] 표시 브랜드는 Maison de Gourmet로 반영됨. 실제 상품 10개 이름, 실물 보상, 적립 시작·종료와 지급 마감은 확정 필요. 기존 event.json은 변경하지 않았습니다.
- [ ] 고정 HTTPS 도메인, 노트북으로의 접근 범위, DNS·인증서·네트워크 연결 확인.
- [ ] **QR URL 직접 열기도 자동 적립될 수 있는 위험** 수용 여부 결정. 브라우저가 정상 사용자 탐색으로 보고한 링크 열기는 카메라 스캔과 구분되지 않습니다. 구매 인증은 없습니다.
- [ ] **직원 인증과 추가 확인 없이 한 번 누르면 지급 완료가 되는 위험**을 직원에게 안내. 고객도 누를 수 있고 오조작을 이 화면에서 취소할 수 없습니다. 실물 지급 후 직원이 누르는 운영 정책이 필요합니다.

## 기존 데이터 보존

- [ ] 변경 전 제공 명령으로 DB를 새 파일에 백업하고 앱을 중지.
- [ ] 기존 data/ 폴더, 실제 event.json, QR 파일, Caddyfile, 도메인·DB 경로를 보존. 새 ZIP의 데모 설정으로 덮어쓰지 않기.
- [ ] 전체 소스와 static/collection-core.js 및 신규 static/stamp-art.js/stamp-art.svg를 함께 교체. DB 초기화·새 이벤트 생성·QR 재발급을 하지 않기.
- [ ] 재시작 전후 기존 고객 표본의 수집 상태와 지급 상태 비교. 기존 개인 복구 링크와 상품별 QR URL로 계속 접근 가능한지 확인.
- [ ] 복원 시험은 원본을 보존하고 별도의 새 DB 경로에서 수행. 이전 백업으로 돌아가면 이후 지급 기록이 사라질 수 있으므로 실물 지급 내역과 대조.

## 실물 휴대폰에서 추가 검증 — 현재 미수행

다음 항목을 실제 **아이폰 Safari / 갤럭시 Chrome**에서 각각 확인하고 기종·OS·브라우저 버전을 기록하세요. BarcodeDetector 지원 여부에 따라 해당 경로와 jsQR 경로를 각각 확인해야 합니다. 자동 테스트는 렌즈·초점·브라우저 영상 처리를 대신하지 않습니다.

| 상황 | 기대 동작 |
| --- | --- |
| QR은 중앙 밖에만 있음 | 적립 0건 |
| 중앙 QR 1개, 주변에 다른 QR 여러 개 | 중앙 십자를 덮고 테두리 안에 온전히 들어온 상품만 적립 |
| 중앙 네모 안에 QR 2개 | 판독 후보가 여러 개면 적립하지 않고 하나만 남기도록 안내. 판독 불가도 적립 0건 |
| QR이 테두리에 걸림 / 십자 바깥 | 적립하지 않음 |
| 세로↔가로 회전, 화면 확대 | 표시 영역과 실제 판독 영역 일치. 회전 중 잘못된 상품 적립 없음 |
| 반사·어두움·가까움·흐림 | 다른 상품으로 적립되지 않음. 판독이 어렵다면 기본 카메라 대안 사용 |
| 같은 QR 계속 비추기 / A→B→A | 상품별 적립 1회, 같은 스캐너 세션의 이미 처리한 QR 재요청 없음 |
| 닫기 / 앱 전환 / 권한 거부 | 카메라 중지, 닫힌 뒤 지연된 인식 결과로 적립하지 않음. 기본 카메라 대안 유지 |
| 처음 방문 | 버튼을 누르기 전 고객/스탬프 생성 없음 |
| 유효한 기존 세션의 새 QR | 탐색 신호가 충분하면 자동 적립 1회. 신호가 없으면 수동 버튼 |
| 링크 미리보기·사전 로딩 | 자동 적립 없음. 해당 앱이 신호를 충분히 제공하는지 실제 확인 필요 |
| 새로고침 / 뒤로 가기 / 앱 전환 복귀 | 추가 자동 적립 없음 |
| 쿠키 삭제·차단·다른 브라우저 | 기존 고객으로 오인하지 않음. 새 고객 버튼 또는 개인 복구 링크로 진행 |
| Safari/Chrome와 카카오톡·네이버 등 앱 내부 브라우저 | 기록이 분리될 수 있음을 안내하고 복구 링크로 올바르게 교체. 자동 병합 없음 |
| 10종 수집→실물 지급→버튼 한 번 | 지급 감사 기록 1개. 완료 버튼 숨김·비활성화, 재방문에도 상태 유지 |
| 버튼 연타 / 응답 유실 / 재시작 | 중복 지급 기록 없음. 재조회하여 이미 완료된 상태를 다시 활성화하지 않음 |

## 노트북 운영

- [ ] 행사 기간에 자동 시간 동기화, 전원·네트워크 유지, 잠자기 해제.
- [ ] 실제 HTTPS에서 Secure·HttpOnly 쿠키와 CSRF 요청이 정상 동작하는지 확인.
- [ ] 30명 동시 접속을 실제 카페 네트워크에서 시험. 현재 HTTP 성능 검사는 노트북 내부 연결만 측정했습니다.
- [ ] 매장 종료 후 등 정해진 주기로 SQLite backup 명령을 사용. 실행 중인 WAL DB 파일 하나만 복사하지 않기.
- [ ] 복구 링크를 비밀 정보로 보관하고 QR 목록·DB·백업을 고객용 웹 경로에 노출하지 않기.

상세 실행법·자동 적립 예외는 README.md, 수행한 검증과 미수행 범위는 TEST_REPORT.md를 참조하세요.
