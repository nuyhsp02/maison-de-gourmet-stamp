# V1.3 모바일 실기기 검증 가이드

대상: **iPhone Safari / Galaxy Chrome**. 이 문서는 검증을 준비하는 안내이며, 실물 기기 테스트를 수행했다는 기록이 아닙니다. 아래 체크는 모두 미수행 상태로 전달합니다.

## 먼저 구분할 것

| 환경 | 사용 목적 |
| --- | --- |
| 노트북 `http://127.0.0.1:8765` | 화면과 API를 노트북에서 미리 보기 |
| 노트북 LAN IP의 신뢰된 HTTPS + 별도 DB | 아이폰·갤럭시 카메라/쿠키/복구를 검증 |
| 실제 운영 주소와 DB | 이번 작업에서 변경·배포하지 않음 |

휴대폰의 localhost는 휴대폰 자신입니다. 노트북과 같은 Wi-Fi에 있어도 휴대폰에 `127.0.0.1`을 입력하면 노트북에 연결되지 않습니다. 일반 `http://192.168...` 주소도 모바일 카메라와 운영용 Secure 쿠키를 검증하는 환경으로 사용하지 않습니다.

카메라의 `getUserMedia()`는 보안 컨텍스트가 필요하고, 운영 식별 쿠키는 Secure 속성을 사용합니다. **인증서 경고 없이 신뢰되는 HTTPS**로 열어야 합니다. 노트북 localhost의 예외는 휴대폰에서 LAN IP를 여는 상황에 적용되지 않습니다. [MDN 카메라 문서](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

## 1. 운영과 분리한 준비

1. 노트북과 휴대폰을 같은 테스트 Wi-Fi에 연결합니다. 게스트 Wi-Fi의 기기 간 접속 차단 여부를 확인합니다.
2. 노트북의 네트워크 설정에서 실제 LAN IP를 확인합니다. 아래 `192.168.0.20`은 예시이며 그대로 사용하지 마세요.
3. 테스트 주소는 운영 호스트와 다르게 선택합니다. **쿠키는 포트로 분리되지 않습니다.** 운영 호스트와 같고 포트만 다른 경우에는 운영과 분리한 테스트 기기/브라우저 저장소가 필요합니다.
4. 기존 event.json과 DB를 복사·이동·초기화하지 않습니다. 제공 도구는 원본을 읽고 새 폴더에 테스트 설정 사본만 만듭니다. DB는 나중에 테스트 서버를 시작할 때 그 폴더에 새로 생성됩니다.
5. 기존 프로젝트 안내대로 Python 가상환경과 의존성을 설치합니다. HTTPS 프록시는 기존 운영 안내에서 사용한 Caddy를 사용합니다. Caddy 설치·실행·인증서 신뢰는 이 작업에서 자동 수행하지 않았습니다.

프로젝트 루트에서 실행하세요.

```sh
.venv/bin/python tools/prepare_mobile_test.py --origin https://192.168.0.20:8443 --out work/mobile-test
```

- `--origin`: 실제 노트북 IP와 전용 HTTPS 포트. 예시는 8443이며 앱 포트 기본값은 8875입니다.
- `--out`: **존재하지 않는 새 폴더**. 기존 폴더와 파일을 덮어쓰지 않습니다.
- `--config`: 생략하면 기존 event.json을 읽습니다. 운영 설정 파일이 다른 곳이면 해당 경로를 지정할 수 있습니다.
- 테스트 설정은 상품 ID·상품명·보상 등을 그대로 복사하고, HTTPS 모드의 기존 시작 조건을 만족하도록 `draft=false`와 약 30일의 테스트 기간만 설정합니다. **원본 event.json은 수정하지 않습니다. 테스트 기간은 실제 행사 일정이 아닙니다.**
- 준비 도구는 서버·Caddy를 시작하지 않으며, DB·인증서를 생성하거나 시스템 신뢰 설정을 바꾸지 않습니다.

생성 파일은 `event.json`, `Caddyfile`, 실행 명령이 적힌 `RUN.md`입니다. 폴더를 옮기거나 노트북 IP가 바뀌면 새 폴더에서 준비하고 테스트 주소와 QR을 다시 확인합니다. 다른 origin의 쿠키·복구 링크는 서로 자동 공유되지 않습니다.

## 2. HTTPS 테스트 서버 시작 — 사람이 직접 실행

생성된 `work/mobile-test/RUN.md`의 명령을 그대로 사용합니다. 아래는 같은 예시 폴더의 명령입니다.

터미널 A:

```sh
.venv/bin/python manage.py --config work/mobile-test/event.json --database work/mobile-test/collection.sqlite serve --public-url https://192.168.0.20:8443 --port 8875
```

터미널 B:

```sh
caddy run --config work/mobile-test/Caddyfile --adapter caddyfile
```

Caddy는 8443에서 HTTPS를 받고 같은 노트북의 `127.0.0.1:8875`로 전달합니다. 생성 설정은 로컬 CA, 테스트 전용 저장 폴더, 관리 API 비활성화, HTTP 리다이렉트 비활성화를 사용합니다. 운영 Caddyfile을 덮어쓰거나 운영 프로세스를 중지하지 않습니다. 이미 포트가 사용 중이면 다른 포트/새 폴더를 사용하세요. 공유기 포트 전달과 외부 공개는 필요하지 않습니다.

인증서와 개인 키는 Caddy를 실제 실행한 뒤 `work/mobile-test/caddy-data` 아래에 생성됩니다. 노트북 인증서 저장소에 자동 설치를 시도하지 않도록 `skip_install_trust`를 설정했습니다. 이 구성 파일은 이번 환경에서 Caddy를 실제 실행하여 검증하지 않았으므로, 기기 연결 전에 설치한 Caddy에서 설정 수락과 기동을 확인해야 합니다. [Caddy 로컬 HTTPS](https://caddyserver.com/docs/automatic-https), [전역 설정](https://caddyserver.com/docs/caddyfile/options)

## 3. 테스트 기기의 인증서 신뢰 — 사람이 직접 확인

공유할 수 있는 것은 **이 테스트 노트북이 생성한 공개 루트 인증서** 한 파일뿐입니다.

```text
work/mobile-test/caddy-data/pki/authorities/local/root.crt
```

테스트 담당자가 노트북과 파일 출처를 확인한 뒤 AirDrop·USB 등으로 테스트 기기에 전달합니다. `root.key`를 포함한 개인 키, DB, Caddy 저장 폴더 전체, 개인 복구 링크는 공유하지 마세요. 인증서 경고 화면의 예외 버튼으로 우회하지 않습니다.

### iPhone Safari

- 전달한 루트 인증서를 설치합니다. OS에 따라 프로파일 설치 단계가 필요합니다.
- `설정 → 일반 → 정보 → 인증서 신뢰 설정`에서 **직접 생성한 테스트 루트**의 SSL/TLS 신뢰를 확인합니다. 수동 프로파일 설치만으로 전체 신뢰가 활성화되지는 않을 수 있습니다. [Apple 공식 안내](https://support.apple.com/en-ca/102390)
- 관리 기기이거나 신뢰 변경이 제한되어 있으면 담당 관리자에게 요청합니다. 다른 루트 인증서의 신뢰를 임의로 바꾸지 않습니다.
- Safari에서 생성한 HTTPS 주소를 열고 인증서 경고가 없는지 확인합니다. 카메라는 웹의 스캔 버튼을 누른 뒤 권한을 요청합니다.

### Galaxy Chrome

- 기기 설정에서 `인증서 설치` 또는 `CA 인증서`를 찾아 직접 생성한 테스트 루트를 설치·확인합니다. One UI/Android 버전에 따라 메뉴와 정책이 다르므로 정확한 화면을 확인합니다.
- Chrome에서 같은 HTTPS 주소가 인증서 경고 없이 열리는지 확인합니다. 관리 정책이 설치를 제한하면 담당 관리자에게 요청합니다. Android 일반 절차는 [Google 인증서 안내](https://support.google.com/pixelphone/answer/2844832?hl=en)를 참고하되 갤럭시의 실제 메뉴를 확인하세요.
- 네이티브 BarcodeDetector 지원 여부와 관계없이 중앙 스캔 동선을 확인합니다. 미지원 기기에서는 포함된 jsQR이 사용됩니다.

테스트 종료 후 테스트 프로세스를 종료하고, 직접 추가한 테스트 인증서/프로파일만 담당자가 제거합니다. 테스트 CA 파일은 코드 ZIP이나 고객 페이지에 올리지 않습니다. 로컬 CA의 개인 키는 비공개로 보관합니다.

## 4. 테스트 QR 생성

휴대폰에서 HTTPS 주소가 경고 없이 열리는 것을 확인한 뒤, 별도 터미널에서 실행합니다.

```sh
.venv/bin/python manage.py --config work/mobile-test/event.json --database work/mobile-test/collection.sqlite qr-export --public-url https://192.168.0.20:8443 --out work/mobile-test/qr
```

노트북에서 `work/mobile-test/qr/index.html`을 열고 휴대폰 기본 카메라로 상품별 QR을 스캔합니다. `manifest.json`의 URL, 서버 public-url, 휴대폰 주소창의 호스트·포트가 같아야 합니다. 이 페이지는 테스트용 QR 모음이며 실제 QR 보드의 크기·덮개·배치를 정하는 자료가 아닙니다.

## 7. 자주 막히는 지점

- 접속 불가: 노트북 IP, 같은 Wi-Fi, 게스트망 차단, 앱/Caddy 실행, 테스트 포트 방화벽 순서로 확인합니다. 기존 운영 서비스를 중지하거나 방화벽 전체를 해제하지 않습니다.
- 인증서 경고: 주소와 인증서 대상, 테스트 루트의 출처·신뢰 상태를 확인합니다. 경고를 무시해 카메라를 시험하지 않습니다.
