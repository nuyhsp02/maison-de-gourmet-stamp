# ADR-013 · 단일 운영 서버의 마감 통제와 서버 밖 백업

- 2026-11-26 사용자는 기존 Lightsail 한 대를 사용하고, 별도 상시 파기 원장 호스트를 두지 않기로 결정했다. 지정 Mac이 꺼져도 고객·직원 서비스, 정기 백업, 만료 처리는 동작해야 한다. 일상 암호문은 생성 시각부터 14일, 행사 종료가 빠르면 그 시각에 만료된다.
- 적용 대상은 로컬 PROD 후보이다. 적립 종료 2027-02-01, 보상 종료 2027-03-01, 접근 종료·파기 기준 2027-03-31은 모두 KST 00:00 배타적 경계다. 기존 가입 승인과 감사자료 처분 승인도 유지한다. [행사 결정](ADR-008-event-lifecycle.md) · [운영 환경](ADR-011-prod-environment-and-enrollment.md)

## 이전 결정을 바꾼 이유

`fd34d16`은 오래된 DB나 서버 이미지로 복원해도 종료 이력을 되돌리지 못하도록 별도 호스트에 상태·시계·관리 권한을 뒀다. 앱은 보호 요청, 쓰기 트랜잭션 및 응답 전달 시 그 호스트에 mTLS로 확인했다. 독립 시각과 신원 검증은 앱 호스트 롤백에 강하지만, 별도 장치의 전원·네트워크·인증서 장애가 정상 영업까지 중단시킨다. 상시 두 번째 호스트를 관리할 비용과 담당자도 필요했다. 이는 코드와 설계에서 확인한 장애 조건이며 실제 고객 장애 실적은 없다. 당시 결정과 구현 근거는 보존한다. [ADR-012](ADR-012-prod-privacy-erasure.md) · [DEV-020](../devlog/DEV-020-prod-privacy-erasure.md)

## 로컬 판단과 외부 증거의 역할

| 상황 | 판단 근거 | 실패 처리 |
|---|---|---|
| 앱 기동과 보호 요청 | 코드가 고정한 행사 경계, Linux 커널의 시각 동기화 상태, 승인 원본 지문, DB 인스턴스, 서비스 DB와 다른 경로의 종료 상태와 마지막 관측 시각 | 시각·승인·파일 또는 바인딩을 확인할 수 없으면 개인 데이터를 제공하지 않는다. 로컬 종료 표시가 있으면 과거 DB만 복사해도 접근이 열리지 않는다. |
| 쓰기·기존 세션 | 쓰기 잠금 획득 뒤, 커밋 직전, 보호 응답 전달 전 다시 검사. 고객·직원·관리자와 운영자 연락처 조회에 같은 마감 적용 | 열린 쿠키의 잔여 수명이 마감을 연장하지 않는다. 정상 동작 중인 고객·직원 화면은 서버가 내려준 남은 시간이 끝나면 표시를 지운다. |
| 종료와 물리 파기 | 영속 systemd 타이머와 다음 기동의 재검사. 승인한 10개 테이블을 트랜잭션으로 처리하고 SQLite 압축·WAL·동기화를 검증 | 접근 종료, 원본 파기 완료, 모든 사본 파기 확인을 따로 기록한다. 승인 부족, 장기 읽기, 알 수 없는 사본, 물리 단계 실패를 완료로 처리하지 않는다. |
| 일상 백업 | Linux 작업이 읽기 전용 스냅샷을 CMS로 암호화하고, 외부 저장소의 버전·크기·체크섬을 확인한다. 수신 영수증·삭제 증거는 별도 버킷에 둔다. | 전송 장애는 재시도하고 미수신을 경보 대상으로 삼는다. 고객 요청에는 저장소를 호출하는 경로가 없다. |
| 수동 복원 | 서버·백업 밖의 승인자 서명, 암호문 수신 및 생명주기 증거, 대상 인스턴스·행사·수신자, 승인 기한과 후보 위치를 복호화 전에 확인 | 미승인·만료·재사용·증거 누락은 거부한다. 종료 후에는 승인된 격리 후보에서만 재파기할 수 있다. |

## 보안 수준과 책임

운영체제 관리자 권한으로 **서버 전체의 DB·로컬 이력·승인 설정을 함께 과거로 복원하고 시각까지 조작**하면 앱에 최신성을 입증할 독립 시계가 없다. 이 상황을 자동으로 탐지하던 종전의 보장을 포기했다. 거점 복구 시 고객 경로를 먼저 닫고, 복구 책임자가 다른 계정·장치에 남긴 승인·마감·수신·파기 증거와 현재 시각을 대조한 뒤 재개한다. 외부 증거까지 유실되면 수동 복원도 보류한다.

외부 저장소의 암호문을 서버가 복호화할 수 없도록 개인키를 분리한다. S3 버전·삭제 마커, 공유 Lightsail 스냅샷, 별도 기기 사본은 각 보관처에서 실제 삭제를 확인해야 한다. 사용자가 이미 저장한 캡처, 전원이 꺼진 기기, SSD·클라우드의 내부 매체 소거까지 앱이 확인할 수는 없다. Mac을 일상 백업 수신 경로에서 제외하고 수동 연습 후 남은 실제 사본은 인벤토리와 처분 기록에 포함한다.

최종 합성 회귀는 Python 478개와 JavaScript 97개가 모두 통과했다. 정상 가입·복구·적립·보상·직원 요청 시 외부 연결 시도는 0건이었다. 원본과 저장소를 끈 뒤 독립 수신 증거와 서명으로 실제 CMS를 격리 복원했고, 임시 Chrome에서도 기한에 열린 카드와 대화상자가 제거됐다. 실제 공급자와 현장 기기 인수는 남아 있다.

시간 검사 방식, 객체 저장소·복원 승인 파일의 구현은 Codex가 선택했다. 실제 버킷·자격·복구 승인자·비용·현장 운영 인수는 사용자와 운영 책임자가 결정한다. [실제 합성 검증과 한계](../devlog/DEV-021-single-server-privacy.md)
