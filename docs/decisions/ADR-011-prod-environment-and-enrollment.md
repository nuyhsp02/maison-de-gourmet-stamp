# ADR-011 · PROD 환경 분리와 실제 고객 가입 정책

- 결정일 — 2026-11-26. 사용자는 PROD의 공용 사이트 입장 비밀번호 제거, DEMO 입장 제한 유지, 실제 가입 전 별도 승인을 확정했다.
- 상태 — 로컬 구현 및 합성 검증. 개인정보 처리의 법적 근거, 실제 고객 가입과 운영 배포의 승인은 남아 있다. [검증 기록](../devlog/DEV-019-production-runtime.md)

## 2026-11-26 후속 결정 · 대표 주소와 공유 서버

사용자는 이미 구매한 도메인의 루트인 `https://gourmetstamp.kr`를 정식 대표 주소로 확정했다. 사전 점검 때 예정했던 `stamp.gourmetstamp.kr`은 만들지 않는다. `www.gourmetstamp.kr`는 기존 경로와 쿼리를 유지한 채 대표 HTTPS 주소로 308 이동한다. 행사 원본 주소와 고객 QR에는 대표 주소 하나를 사용한다.

기존 Lightsail의 80·443은 Nginx가 호스트 이름으로 구분한다. DEMO의 기본 서버·도메인 인증서·Basic Auth·Waitress 8875를 보존하고 PROD는 이름을 명시한 블록과 Waitress 8876을 사용한다. PROD 인증서에는 루트와 `www`가 함께 필요하다. DNS는 두 A 레코드만 전환한다. 실제 DNS 전환·인증서 발급·배포는 별도 승인 대상이다. [공유 Nginx와 DNS 전환](../PROD_RUNTIME.md#공유-nginx와-dns-전환)

## 입장, 카드 찾기, 직원 권한

DEMO는 매장 관계자에게만 보여 주므로 Nginx의 Basic Auth와 입장 자격 파일을 유지한다. PROD 상품 QR은 고객이 휴대폰으로 바로 열어야 하므로 공유 비밀번호가 없다. PROD 가상 호스트는 상위 Nginx 설정에서 상속될 수 있는 입장 인증도 명시적으로 끈다. 카드와 정적 파일을 읽을 권한, 신규 가입 정책, 직원 통계·취소·관리자 정정 권한은 각각 해당 서버 경로에서 결정한다. 데이터 조회에는 기존 이름·전화번호 일치 또는 세션이 필요하다. [PROD Nginx](../../deploy/linux/nginx-prod.conf) · [직원 권한](../../app/staff_admin.py)

새 PROD 행사 DB에는 DEMO 고객·적립·세션·QR을 가져오지 않는다. 고객은 이름과 전화번호로 한 번 가입하고, 기기를 바꾸면 두 값으로 같은 카드를 찾는다. PROD는 개인 링크 페이지와 발급·사용 API를 등록하지 않고 복구 토큰 테이블도 생성하지 않는다. 이름과 번호를 함께 아는 사람이 카드를 찾을 수 있다는 기존 정책의 한계는 남는다. [카드 복구 정책](ADR-010-prod-card-recovery.md)

## 가입 승인 증거

기존 `SyntheticEnrollment`는 허용된 합성 프로필만 받는다. PROD의 `ProductionEnrollment`는 별도 형식의 행사별 수신 공개키와 가입 정책을 검증한다. 승인 문서의 정확한 바이트에 대한 SHA-256을 서비스 시작 설정에서 독립적으로 지정한다. 운영 책임자는 변경 권한을 제한한 두 경로를 관리하고, 승인 문서·정책 버전·지문의 대응을 인수 기록에 남긴다. 지문만으로 승인자의 신원이나 법적 타당성이 증명되지는 않는다.

가입에는 매장 승인 시점, 목적, 처리 근거 문서 참조, 보유기간, 문의처, 행사·연락처 수신키, 안내 문구와 버전이 필요한 구조다. 안내 확인 체크박스는 **‘개인정보 처리 안내를 확인했습니다.’** 한 개다. 앱은 화면에 표시한 버전과 제출 버전을 대조하고 쓰기 잠금을 얻은 뒤에도 승인이 유효한지 확인한다. 정책이 없거나 철회되면 가입 요청은 `403 registration_closed`로 끝나며 기존 카드는 찾을 수 있다. 승인 정보가 없는 배포용 서비스 유닛은 이 상태로만 기동한다. [연락처 설계](ADR-007-contact-privacy.md) · [가입 정책](../../app/contact_privacy.py)

## 환경과 키의 경계

기존 DEMO 실행기에 모드 하나를 추가하면 설정 실수로 공개 대상과 DB를 뒤바꿀 수 있다. 독립 Linux 진입점, OS 서비스 계정, 상태 디렉터리, 신규 DB 식별자와 키를 두고, 고객·직원 도메인 로직은 공유한다. 초기화는 비어 있는 곳에서만 가능하며 정합성 검사가 끝난 DB와 프로필 키를 한 디렉터리로 공개한다. 부팅 시 저장된 스키마·행사·상품·수신자·QR과 독립 자격을 검증한다. 별도의 명령과 인수 절차를 유지해야 하지만, 이전 환경의 자격이나 잘못된 백업을 단순 복사해 시작하는 실수를 차단한다. [Linux 진입점](../../deploy/linux/prod.py) · [암호화 복원](../../deploy/linux/prod_backup.py)

전화번호 HMAC 키, 연락처 수신 공개키, 서버 밖의 복호화 개인키, 두 역할의 비밀번호 검증 파일, 상품 QR 키의 용도를 분리한다. 지정 운영자만 SSH 강제 명령으로 한 건을 요청한다. 서버의 조회 감사 기록이 커밋된 뒤 암호문을 전달하고, 지정 Mac에서만 번호를 표시한다. [운영자 통로](../../deploy/linux/prod_contact_ssh.py) · [Mac 보관 도구](../../tools/contact_mac.py)

상품 스탬프 10종의 확인된 허가는 비상업적 포트폴리오 사용이다. PROD 고객 화면은 중립적인 번호 표시를 사용하고 PROD 패키지에서는 원본과 DEMO 카탈로그를 제외한다. 상품 사진이 없는 이번 버전에서 `image: null`은 의도적으로 사진을 표시하지 않는 선택이다. [자산 사용 범위](../ASSET_ATTRIBUTION.md) · [운영 인수 절차](../PROD_RUNTIME.md)
