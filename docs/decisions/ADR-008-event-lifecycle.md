# ADR-008 · 적립·보상·고객 접근과 개인정보 파기의 경계

- 상태 — 적립·보상 기간 분리는 기존 코드에서 확인했습니다. 2월 취소 권한과 3월 말 고객 접근·파기는 2026-11-25 사용자가 결정한 PROD 요구이며 구현 전입니다.
- 관계 — [ADR-006](ADR-006-unauthenticated-redemption.md)의 실물 지급 후 카드당 1회 처리와 [ADR-007](ADR-007-contact-privacy.md)의 연락처 보호를 이어갑니다. [결정 출처](../evidence/portfolio-milestones-20261125.md#사용자-결정)

## 1. 해결하려던 문제

1월에 스탬프를 모두 모은 고객은 2월에도 보상을 받을 수 있어야 합니다. 적립이 끝난 뒤 직원이 완성 카드에서 도장 하나를 지우면 고객은 다시 10개를 만들 수 없습니다. 지급 종료 후에도 조회할 기간과 고객 접근·개인정보 보관을 끝낼 기준이 필요했습니다.

## 2. 고려한 대안과 기록의 한계

D86에는 적립과 보상을 함께 마감하는 제안이 있었고 D87에서 보상 기간을 연장했습니다. 1차 준비도 조사에서는 2월 취소 차단과 제한된 예외 처리를 검토 대상으로 남겼습니다. 그 뒤 사용자가 일반 직원 취소 차단과 관리자 예외 정정을 함께 선택했습니다. 과거의 ‘최대 30일’ 예시나 Windows 백업 설정에서 이번 파기일을 계산한 것은 아닙니다.

## 3. 최종 선택

| KST 배타적 경계 | 직전까지의 권리 | 정각부터 적용할 PROD 정책 |
|---|---|---|
| `ends_at = 2027-02-01T00:00:00+09:00` | 1/31 하루 전체까지 상품별 적립 | 신규 적립과 일반 직원 취소 차단. 관리자 예외 정정에는 사유와 감사 기록 필수 |
| `reward_until = 2027-03-01T00:00:00+09:00` | 2/28 하루 전체까지 기존 조건을 충족한 미수령 카드의 1회 보상 | 신규 보상 수령 종료. 3월에는 고객 조회 허용 |
| `2027-03-31T00:00:00+09:00` | 3/30 하루 전체까지 고객 조회 | 고객 접근 종료 및 개인정보 파기 기준 도달. 3/31 하루를 추가로 허용하지 않음 |

3/31은 파기와 접근 종료의 **운영 기준**입니다. 예약 작업 존재나 삭제 실행 완료를 뜻하지 않습니다. **백업 보유기간 14일은 승인되지 않았습니다.**

## 4. 기술적 선택 근거

코드에서 확인한 동작은 적립 서버가 쓰기 직전의 적립 가능 기간을, 보상 서버가 별도의 지급 가능 기간과 기존 수령 여부를 검사한다는 것입니다. 배타적 경계는 마지막 날 23:59:59 이후의 소수 초도 포함합니다.

사후 설계 해석으로는 취소·예외 정정·개인정보 파기에 각각 다른 권한과 증거가 필요합니다. 적립 가능 여부 한 값으로 함께 제어하면 2월의 정당한 지급이나 3월 조회까지 막을 수 있습니다.

## 5. 단점과 위험

`aaccb50`의 직원 취소는 수령 여부와 조회 당시 상태를 검사하지만 날짜별 권한, 사유를 가진 상위 관리자 예외 경로는 없습니다. 현재 카드 조회·찾기·복구 링크에는 3/31 차단도 없습니다. 화면을 닫는 것만으로 기존 쿠키나 링크를 통한 요청은 끝나지 않습니다. 이전 백업을 복원하면 지운 연락처가 되살아날 수 있어 사본 만료와 복원 후 재처리 절차가 필요합니다.

## 6. 실제 코드 및 테스트 근거

[행사 검증·적립·지급](../../app/app.py)의 `phase`, `reward_open`, `collect`, `redeem`과 [직원 취소](../../app/staff_admin.py)의 `admin_cancel`을 대조했습니다. [기존 기간 시험](../../app/tests/test_collection.py)과 [출시 조사 기록](../devlog/DEV-013-prod-readiness.md)의 여섯 시점 검산은 앞의 두 경계를 뒷받침합니다. 신규 관리자 예외·3/31 파기 시험은 미실행입니다.

## 7. 향후 개선 가능성

관리자 예외 정정의 허용 범위, 담당자 인증과 감사 항목을 구체화하고 일반 직원·권한 있는 관리자 각각의 마감 직전/정각 동작을 시험해야 합니다. 3/31에는 기존 세션·찾기·링크를 포함한 접근 종료와 파기 대상별 검증을 준비합니다. 백업 만료, 삭제 후 복원, 감사 이력의 보존 범위와 담당자는 별도 확정 사항입니다.
