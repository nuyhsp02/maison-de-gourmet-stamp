# ADR-010 · PROD 신규 DB와 고객 카드 복구 정책

- 결정일 — 2026-11-25, 사용자 확정.
- 상태 — PROD 설계 결정. 이번 구현에서는 고객 등록, 카드 찾기, 복구 링크 발급·사용 코드를 그대로 유지한다. PROD 개설과 링크 제거는 후속 작업이다.

## 고객 진입과 복구

PROD는 새 행사 DB로 시작한다. DEMO의 고객, 세션, 적립·보상 이력, 복구 토큰과 상품 QR 키를 이관하지 않는다. 신규 고객은 이름·전화번호로 프로필에 가입한다. 쿠키 삭제나 기기 변경 후에는 이름과 정규화된 전화번호가 일치하는 기존 카드를 찾는다. 동일한 번호로 카드를 추가 발급하거나 기존 이력을 병합하지 않는다. 전화번호 검색 및 유일성에는 HMAC을 계속 사용한다. [프로필 설계](../PR1_CUSTOMER_PROFILES.md) · [연락처 보호](ADR-007-contact-privacy.md)

## 개인 복구 링크 처리

기존 DEMO는 발급된 링크로 같은 카드를 복구할 수 있다. PROD에서는 이름·전화번호 방식으로 복구 경로를 통일하고 개인 복구 링크를 제공하지 않는다. 신규 DB를 사용하므로 DEMO 링크 소지자에게 PROD 카드 접근권을 이전할 필요가 없다. PROD에서 버튼만 숨기면 링크 API가 남는다. 후속 구현에서는 화면 노출과 서버의 발급·사용 경로를 함께 점검하고, 기존 DEMO 경로가 계속 동작하는지 별도로 검증한다. [기존 익명 식별 결정](ADR-002-anonymous-identity.md) · [현재 고객 API](../../app/app.py)

## 한계와 후속 인수 조건

이름과 전화번호를 아는 사람의 복구 위험은 남는다. 임의의 추가 본인인증 절차는 이 결정에 포함하지 않았다. 후속 작업의 인수 조건은 독립된 합성 PROD 설정에서 프로필 가입, 새 브라우저의 같은 카드 복구, 이름 불일치 차단, 개인 링크 발급·사용 차단, 별도 DEMO 설정에서 기존 링크 호환을 확인하는 것이다. 실제 고객 가입에는 개인정보 처리 근거와 운영 승인도 필요하다. [행사 및 접근 종료 정책](ADR-008-event-lifecycle.md)
