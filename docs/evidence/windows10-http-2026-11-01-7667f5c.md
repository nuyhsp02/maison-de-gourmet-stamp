## HTTP 집계 — 전체 관측 400건

| 결과 | 건수 | 구분 |
|---|---:|---|
| HTTP 200 | 396 | 성공 응답 |
| HTTP 400 | 1 | 의도적 거부 |
| HTTP 409 | 1 | 의도적 거부 |
| HTTP 503 | 1 | 의도적으로 유발한 admission timeout |
| 응답 유실 (`None`) | 1 | 의도적 응답 유실. HTTP 응답 코드가 아님 |
| 합계 | **400** | `396 + 1 + 1 + 1 + 1` |

제공 집계에서 503은 통제한 **1건**이며 자연 발생 503로 세지 않는다. 이 회차의 전달 집계에 추가 자연 503은 없지만, 과거 간헐 timeout의 근본 원인 해결 증거는 아니다. 전체를 단순한 실패율 4/400 또는 운영 성공률로 계산하지 않는다.

### 동시 `/api/collect` — Windows 10 loopback 관측

| 독립 HTTP 세션 | HTTP 200 / 적립 요청 | p95 (ms) | p99 (ms) | 최대 (ms) |
|---|---:|---:|---:|---:|
| 5 | 25 / 25 | **65.790** | **75.461** | **75.461** |
| 10 | 50 / 50 | **78.196** | **81.384** | **81.384** |
| 30 | 150 / 150 | **111.641** | **131.806** | **132.843** |

동시 적립 표본은 합계 **225/225 HTTP 200**이다. 도구는 단계별 5회 burst·회차 사이 10초 휴식을 사용한다. 30세션은 휴대폰 30대나 카페 고객 30명의 실사용 측정이 아니다. 원본 400명·동시 30개/5,200 POST 부하 검사의 재실행 또는 대체 결과도 아니다.

의도적 admission 503 응답 시간은 **15026.999ms**이다. 원래 15초 경로의 관측값이며 정상 요청 지연과 합치지 않는다. 잠금 보유 구간이나 과거 자연 오류 원인을 이 값으로 추정하지 않는다.

위 분위수는 전달받은 값이며 원시 표본으로 재계산하지 않았다. 전체 400건의 지연·중앙값·경과 시간·완료 요청/s는 미제공이다. 특히 25·50개 표본의 p99는 작은 표본의 한계가 있다. [운영 수용 제안값](../WINDOWS_ACCEPTANCE.md#3-운영-수용-기준-제안--승인-전)은 **미승인**이며 이 결과를 보고 소급 승인하거나 HTTPS/LTE·장시간 운영 성능으로 일반화하지 않는다.
