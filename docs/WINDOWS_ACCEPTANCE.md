# 실제 Windows 인수 검증표 — 모두 미실행

이 표는 **아직 테스트 결과가 아니라 수행 절차**입니다. 작성자/날짜/OS 빌드/Python/cloudflared 버전/설치 경로/결과/증거를 적으세요. 처음에는 테스트용 별도 폴더·테스트 이벤트·테스트 DB만 사용합니다. 운영 DB를 손상시키거나 테스트 고객을 실제 DB에 만들지 않습니다. 실제 연결 검사는 담당자가 정식 도메인 공개를 결정한 뒤 수행합니다.

## iPhone Safari / Galaxy Chrome — 각각 체크

두 브라우저 모두 실기기 검증을 수행하지 않았습니다. Windows 서버 동작과 별개로 각 항목을 따로 기록합니다.

- [ ] 기본 카메라로 상품 QR 첫 접속 → 새 카드 만들기 버튼 → 해당 상품 1회 적립.
- [ ] 같은 브라우저 재방문 QR → 정상 세션의 조건부 자동 적립, 동일 상품 안내/새로고침 중복 없음.
- [ ] 미리보기/프리패치만으로 카드/적립 생성 없음. 앱의 GET은 계속 읽기 전용.
- [ ] 개인 복구 링크 저장·동일/다른 브라우저 복구, 완료/지급 상태도 보존.
- [ ] 연속 카메라 스캔: 중앙 영역 안 단일 QR만 적립, 영역 밖/여러 QR/회전·object-fit·카메라 전환 점검.
- [ ] 같은 QR 연속 인식/2~3종 구매/권한 거부 시 기본 카메라로 하나씩 스캔하는 대안.
- [ ] 인앱 브라우저와 기본 Safari/Chrome 간 쿠키 분리, 외부 브라우저로 열기 안내.
- [ ] 10종 수집 → 지급 대기 → 실제 지급 후 버튼 1회 → 반복 요청/재시작에도 지급 기록 1개.
- [ ] iPhone SE급 좁은 화면과 Galaxy 세로 화면의 트리 1·2·3·4, 민트/레드 상태, 버튼 겹침 없음.
- [ ] 이벤트 종료 후 기록 유지/적립 종료/보상 기한 처리. 실제 날짜를 운영 중 임의 변경하지 않고 테스트 이벤트에서 확인.

## 운영 시작 전 필수 결정

정식 도메인, 실제 기간/상품/보상, 이벤트 ID/기존 DB 이관, OS 보안 업데이트, 외부 백업 매체, 운영 책임자, 절전/전원·인터넷 중단 대응을 확인합니다. 위 미실행 검증을 통과했다고 자동으로 표시하지 마세요.
