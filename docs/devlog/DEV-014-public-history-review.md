# DEV-014 · 공개 저장소 이력 및 개인정보 공개 검수

- 기록일 2026-11-25. 기존 Git 객체와 작업 파일을 직접 대조한 조사·수정 기록.
- 기준은 공개 main `cceed35`, 공개 Draft PR #4 `ed9912a`, 로컬 `feature/contact-privacy-admin`이다. 이번에 처음 이메일이 입력된 날짜는 조사하지 않았다.
- 실행 주체는 사용자 승인을 받은 Codex다. 사용자는 카페 그림의 공개 허가 자료가 아직 없다고 확인했다. 소유자가 직접 검사를 재현한 범위는 미확인이다.
- 상태는 로컬 이력 정비와 합성 시험 완료, 전체 브랜치 공개 보류다. 아래 SHA는 소스의 식별자다. 검수 도구 및 문서 편집은 미커밋 상태에서 검증했다.

## 1. 문제와 예상 동작

소스 파일을 검사해도 Git의 작성자·커미터 필드에 든 개인 주소가 공개될 수 있다. 기존 검사로 놓쳤던 두 필드를 검증하고, 이미 공개한 22개 커밋과 과거 배포·검증 결과의 출처를 보존해야 했다.

## 2. 관측과 원인

공개 PR 끝에서 미공개 커밋 8개가 차례로 이어졌다. 8개 모두 두 이메일 필드에 정비 대상 주소가 있었다. 기존 도구는 커밋 원문도 토큰·키 등의 패턴으로 검사했지만 두 신원 필드의 허용 주소를 판별하는 규칙이 없었다. PR 문서 3개의 내부 설계 링크 6개는 서로 다른 페이지 4개를 가리켰다. 주소 형식은 ChatGPT Space였다.

## 3. 해결 또는 조사 과정

1. 기존 브랜치 bundle, 옛 HEAD, 원격 설정, 미스테이징 패치와 문서 11개 원본을 작업 폴더 밖에 보관했다. bundle과 개별 파일 해시를 검증했다.
2. GitHub 계정 조회로 소유자의 로그인과 숫자 ID를 확인하고 저장소 로컬 설정에 해당 noreply 주소를 적용했다. 공개 PR 끝을 부모로 유지하고 8개 커밋의 이메일과 바뀐 부모 SHA만 교체했다. 다른 참조는 보존했다.
3. PR 1~3 설명은 유지하면서 작업 문서의 내부 링크를 저장소 내 ERD·구현 기록으로 교체했다. README에서 Windows V1.4.0, 현장 확인을 받은 Ubuntu 비공개 DEMO, 실고객 가입을 보류한 로컬 후보를 구분했다.
4. 그림은 공급 기록·원본과 대조하고 직원 화면은 합성 데이터 생성 경로와 실제 픽셀을 확인했다. 소스 반입과 공개 재배포 허가를 따로 확인했다.

## 6. 미검증 사항과 후속 확인

- **내부 주소**는 첫 미공개 커밋부터 과거 파일에 남는다. 다음 커밋에서 문서를 고쳐도 공개할 수 있는 이력이 되지 않는다. 공개하려면 기존 공개 22개를 고정하고 미공개 커밋의 **파일 트리 변경**을 허용하는 별도 결정이 필요하다. 그러면 위 새 SHA도 다시 바뀐다.
- **카페 그림 10개**는 원본을 내려받을 수 있는 공개 GitHub 재배포와 취업 포트폴리오 공개 사용의 허가 자료가 없다. 두 범위를 권리자에게 확인해야 한다. 허가를 받지 못하면 과거 커밋까지 제외하는 방법과 공개용 대체물 사용 여부를 먼저 승인받는다.
- 서비스 경로 예시, 합성 번호·LAN 주소 예시, DEMO 카탈로그 식별자는 코드와 테스트에 남는다. 카탈로그 식별자는 시연 구성과의 대응을 보여 주며 인증 자격은 아니다. 패턴 검사는 모든 개인정보나 의도적으로 숨긴 데이터를 판별할 수 없다.
- 미스테이징 문서와 도구는 검토용이다. 두 차단 항목 해결 후 실제 공개 후보를 다시 검사하고 별도 승인을 받아야 한다. PROD 공개와 운영은 이 검토 범위 밖이다.
