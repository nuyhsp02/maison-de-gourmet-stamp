# DEV-001 · 브라우저 캐시 및 JavaScript 버전 불일치 — 미확인 사례 조사

- 기록 유형: 문제 유형 조사 / 근거 부족을 표시한 회고 항목.
- 문제 발생일·브라우저·당시 배포 버전: **미확인**.
- 기준: [V1.4.0 / 1284c52](https://github.com/nuyhsp02/maison-de-gourmet-stamp/commit/1284c52e04e5e323af4a7fb182d78a2b27a01b8f).
- 실행 주체/참여: 이번 문서화에서 코드·기존 기록을 대조. 소유자의 당시 브라우저 재현/해결 경험은 확인할 근거가 없음.

## 1. 문제와 예상 동작

기록 요청에 포함된 주제는 HTML과 JavaScript가 다른 버전으로 제공되는 상황입니다. 현재 저장소에는 그 사건의 화면, Network 응답, 오류 메시지, 재현 순서가 없습니다. 실제 발생을 확인한 해결 사례로 서술하지 않습니다. 기대 조건은 같은 배포의 화면/스크립트가 함께 동작하는 것입니다.

## 2. 관측과 원인

확인한 현재 코드:

- [index.html](../../app/templates/index.html)은 jsQR → collection-core → stamp-art → app 순으로 고정 경로의 스크립트를 로드합니다. 해당 src에는 버전 해시가 없습니다.
- [app.py](../../app/app.py)의 `security_headers`는 `Cache-Control: no-store`를 설정합니다.
- [app.js](../../app/static/app.js)의 API 요청 옵션에도 `cache: 'no-store'`가 있습니다. 이것만으로 스크립트 파일의 버전 일치를 검증하는 것은 아닙니다.

오래된 브라우저 캐시, 일부 파일만 교체한 배포, 중간 캐시의 응답 변경은 **확인할 가설**입니다. 이 프로젝트에서 어느 것이 실제 원인이었는지는 미확인입니다. no-store가 존재한다는 사실과 해당 사건 때문에 추가됐다는 주장은 다릅니다.

## 3. 해결 또는 조사 과정

이번 작업에서는 템플릿·응답 헤더·API 요청·기존 테스트/문서를 읽었습니다. 브라우저에서 과거 버전 혼합을 재현하거나 캐시를 삭제해 해결한 실험은 수행하지 않았습니다. [기존 배포 전 안내](../../app/PRE_DEPLOY_CHECKLIST.md)에 전체 소스를 함께 교체하라는 절차가 있으나, 특정 캐시 사건의 해결 기록은 아닙니다.

## 4. 코드 변경

이 기록에서 확인할 수 있는 캐시 사건의 수정 커밋은 **미확인**입니다. 기존 no-store 정책을 새로 구현한 것처럼 쓰지 않습니다. 이번 작업도 앱·자산 URL·배포 설정을 바꾸지 않는 문서화입니다.

## 5. 검증 결과

[test_v11.py](../../app/tests/test_v11.py)의 `test_navigation_hint_is_read_only_and_prefetch_fails_closed`와 [test_collection.py](../../app/tests/test_collection.py)의 보안 헤더 검사는 no-store 정책의 일부 근거입니다. [test_v13.py](../../app/tests/test_v13.py)의 자산 로드 순서/응답 검사는 현재 자산 구성을 확인합니다.

이 결과는 과거 캐시 불일치 재현, 모든 정적 자산의 캐시 동작, 실제 브라우저 간 버전 혼합의 해결을 증명하지 않습니다. 이 사례를 위해 새 브라우저 테스트를 실행한 결과는 없습니다.

## 6. 미검증 사항과 후속 확인

격리된 테스트 배포에서 HTML/스크립트 응답과 파일 해시·기준 커밋을 대조하고, 캐시 상태/전체 또는 부분 교체 조건을 기록해야 합니다. 이 절차는 **아직 미실행**입니다. 재현되면 원인별 대응을 결정하고 실제 diff/전후 결과를 추가합니다. 버전 해시 도입도 현재는 개선 후보일 뿐입니다.
