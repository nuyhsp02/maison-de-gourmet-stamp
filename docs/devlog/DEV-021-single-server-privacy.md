# DEV-021 · 외부 원장 없이 마감·백업·복원 검증

- 기준은 `feature/contact-privacy-admin`의 `444b828`이다. 2026-11-26 사용자는 기존 Lightsail 한 대 유지, 지정 Mac의 상시 접속 제거, 일상 백업 14일과 행사 마감 우선 적용을 결정했다. Codex가 로컬 구현과 합성 시험을 수행했다. 실제 운영 배포 및 사용자의 직접 재현은 별도 인수다. [ADR-013](../decisions/ADR-013-single-server-privacy.md)
- `fd34d16`의 네트워크 원장은 손상된 운영 호스트가 단독으로 마감을 되돌리는 것을 어렵게 했다. 별도 호스트나 mTLS 통신이 멈추면 정상 카드·직원 요청도 실패한다는 결합을 코드에서 확인했다. 실제 고객 장애가 발생했다는 기록은 없다. [이전 구현](DEV-020-prod-privacy-erasure.md)

## 검증 환경과 인수 경계

검증용 Ubuntu에서 임시 DB, 자체 발급한 시험 인증서, 가상 행사 시각, 합성 객체 저장소와 AWS CLI 응답을 사용했다. 앱·백업·복원 분리와 이전 DEMO 흐름은 자동 회귀 대상으로 유지한다. 외부 네트워크를 끄고도 로컬 Nginx·Waitress와 고객·직원 인증을 실제 통신으로 시험한다. 클라우드 연동·실제 키·Lightsail·전화기 화면은 이번 검증에 포함하지 않는다.

```sh
MAISON_HTTPS_TEST=1 MAISON_HTTP_TESTS=1 python -B -m pytest -q -p no:cacheprovider -ra --tb=short app/tests tests
node --test app/tests/*.test.cjs
python -B -m pytest -q -p no:cacheprovider tests/test_repository.py
```

이번 최종 실행은 Ubuntu 24.04.5, Python 3.12.3, SQLite 3.51.3, Node 18.19.1, Nginx 1.24.0에서 수행했다. **Python 478/478**(434.11초, 앱·운영 427개와 저장소 검수 51개), **JavaScript 97/97**(3.55초)으로 실패·건너뜀은 모두 0건이었다. 중복 집계 없이 저장소 검수 51개도 별도로 다시 통과했다. 앞선 릴리스 보고의 445/94와 구분한다.

Ubuntu의 systemd 255에서 웹·파기·백업 서비스 및 타이머 5개의 정적 검사를 통과했다. 격리 커널의 시간 동기화 상태는 미확인(TIME_ERROR)이었고 실제 시스템 호출이 이를 거부했다. 정상 시각의 업무 흐름은 합성 시각으로 검증했다. 실호스트에서는 NTP 상태와 부팅 직후의 재시도, 백업 수신 경보, 서명 복원, 모든 스냅샷·오프라인 사본 재고를 인수해야 한다. [운영 절차](../PROD_RUNTIME.md) · [복원과 만료](../PROD_BACKUP_EXPIRY.md)

별도 통합 시험에서는 실제 온라인 스냅샷과 CMS, 버전 저장소에 발행한 수신·정책·종료 상태 원본을 그대로 사용했다. 저장소와 원본 서비스를 끊은 뒤 다른 복원대장에서 OpenSSL 서명·암호문·복원 결과를 확인했다. 합성 카드 1개·프로필 1개·스탬프 1개와 상품 10개가 보존됐고 직원 세션은 0개였다. SQLite 무결성은 `ok`, 외래키 위반은 0건이었다.

macOS의 임시 Chrome 158 프로필에서도 실제 화면을 확인했다. 시험 페이지의 1.3초 기한 전에는 합성 카드와 대화상자가 보였고, 기한이 되자 대화상자가 닫히고 카드가 DOM에서 제거된 뒤 종료 경로로 이동했다. OS가 보관한 화면 캡처나 실제 휴대폰의 절전·복귀 동작은 실기기 확인 항목이다.

## 직접 설명하고 재현할 질문

1. DB만 과거로 바꿀 때와 관리자 권한으로 서버 전체와 시각을 되돌릴 때 각각 어떤 증거를 신뢰할 수 있는가?
2. 데이터를 지운 SQLite 트랜잭션, WAL 정리, 원본 파기 영수증, 외부 버전 삭제 영수증은 왜 따로 확인하는가?
3. PUT 직후 통신을 끊고 재시도해 보라. 같은 CMS와 같은 수신 영수증을 어떻게 알아보고, 삭제 마커 한 개로는 왜 충분하지 않은가?
4. Mac을 끈 상태와 백업 저장소를 차단한 상태를 구분해 보라. 어느 시점에 사용자 응답, 저장소 상태, 경보가 각각 바뀌는가?
5. 서명한 복원 결정을 다른 목적지로 바꾸거나 재사용해 보라. 어느 파일·DB 제약이 개인 데이터 제공을 막는가?

직접 훈련한 날짜, 실패·재시도 증거와 본인의 설명은 운영자가 실제 훈련을 마친 뒤 기록한다.
