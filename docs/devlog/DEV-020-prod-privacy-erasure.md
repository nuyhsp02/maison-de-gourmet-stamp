## 검증 범위

테스트는 소유권을 가진 임시 디렉터리, 일회용 자격·프로필, 가상 시각을 사용한다. 실제 고객 카드나 운영 데이터는 시험 대상이 아니다. 집중 시험에서 의도적으로 손상된 rollback journal을 둔 뒤 비교용 조회를 하자 SQLite가 읽기 전용 연결에서 복구를 시도해 시험 준비가 실패했다. 해당 거부 시험을 파일 바이트 전후 비교로 수정해 불완전한 파일에 애플리케이션이 쓰지 않았음을 직접 확인했다. ## 이번 로컬 실행 결과

인터넷과 호스트 저장장치 공유를 끈 Ubuntu 24.04.5에서 Python 3.12.3, SQLite 3.51.3, Node.js 18.19.1, Nginx 1.24.0을 사용했다. Python 전체 **445/445**(343.01초) 중 앱·운영 394개, 저장소 보안 검수 51개가 통과했다. JavaScript 전체는 **94/94**다. 두 전체 실행에서 실패·건너뜀은 0건이다.

```sh
MAISON_HTTPS_TEST=1 MAISON_HTTP_TESTS=1 python -B -m pytest -q -p no:cacheprovider -ra --tb=short --junitxml=/tmp/regression.xml app/tests tests
node --test app/tests/*.test.cjs
```

중간 Linux 집중 실행에서 권한 거부 시험 하나가 실패했다. 프로세스의 umask 0077이 생성 권한 0755를 0700으로 줄여 시험 의도와 다른 안전한 디렉터리가 생긴 것이 원인이었다. 시험에서 chmod로 실제 0755를 만든 뒤 위 전체 회귀를 실행했다. systemd 255에서 웹 서비스와 파기·만료 서비스/타이머 다섯 파일을 오프라인으로 검사하고 두 예약식의 다음 실행 UTC가 동일함을 확인했다. 실제 타이머 등록과 실물 호스트 부팅은 운영 인수 사항이다.

## 남은 운영 인수와 직접 재현

운영자가 확정할 사항은 일상 백업 보유기간, 감사 자료별 보존·파기 권한, 개인정보 처리 근거·고객 안내, 독립 원장 호스트·수탁자, 모든 저장 매체와 제공자별 버전 삭제 증거다. 시계 동기화·장애 경보·재부팅, 복원·종료 공지의 실기기 검수도 남아 있다. [운영 절차](../PROD_RUNTIME.md)

1. 요청이 마감 직전에 시작하고 SQLite 쓰기 잠금을 얻은 뒤 시각이 바뀌는 상황에서 어느 검사가 커밋을 막는지 설명한다.
2. WAL에 오래된 읽기 연결을 유지한 합성 DB에서 논리 행이 0개인 시점과 물리 정리 영수증을 발행할 수 있는 시점을 비교한다.
3. 과거 합성 사본과 프로필 키를 함께 복원한 뒤 왜 새 서비스 세션이나 전체 번호를 얻을 수 없는지 재현한다.
4. 원장에 DB 완료만 남기고 보관소 한 곳을 분리한다. 전체 만료로 결론 내릴 수 없는 이유와 필요한 추가 증거를 설명한다.

직접 재현한 날짜, 사용한 합성 자료와 자신의 설명은 실제 수행 후 기록한다.
