# DEV-017 · 일반 직원 취소 마감과 관리자 예외 정정

- 작업·검증일 — 2026-11-25~26 KST. 실제 고객 사고의 발생 기록은 없다. 사용자가 확정한 보상 보호 정책을 로컬 합성 환경에서 구현하고 검증한 기록이다.
- 기준 — `feature/contact-privacy-admin`의 `19b08b4`와 그 위의 미커밋 일반 직원 마감 변경 세 파일. 이번 작업도 로컬 검토 대상으로 남겼다.
- 역할 — 사용자가 기간·허용 작업·보상 자격·기록 정책을 정했다. AI 도구가 구현, 테스트 작성 및 실행을 맡았다. 소유자의 직접 재현과 매장 확인은 대기 중이다.

## 문제와 설계

직원이 1월 31일 밤 요청하더라도 다른 연결이 SQLite 쓰기 잠금을 먼저 갖고 있으면 실제 처리는 2월이 될 수 있다. 화면을 열었던 시각이나 요청 도착 시각만 검사하면 완성 카드에서 스탬프를 지울 수 있다. 기존 일반 취소 API는 유지하고, 오류 정정은 별도 관리자 자격·별도 API·별도 감사 테이블로 분리했다. [행사 정책](../decisions/ADR-008-event-lifecycle.md) · [대안과 결정](../decisions/ADR-009-stamp-corrections.md)

## 구현에서 확인할 지점

1. 사용 중인 직원 자격은 그대로 유지한다. 관리자 자격은 `python app/manage.py --database <합성-DB-경로> manager-password --actor <관리자-ID>`로 대화형 터미널에서만 설정한다. 역할은 서버가 검증한 자격에서 결정한다. 정정 화면의 선택이나 요청 본문으로 승격할 수 없다. [자격 설정](../../app/manage.py) · [세션 처리](../../app/staff_admin.py)
2. 적립 중 일반 취소와 2월 예외 정정은 서버의 같은 행사 설정을 읽는다. 관리자 정정은 쓰기 잠금을 취득한 후 역할·CSRF·기간을 다시 확인한다. 완성·지급 카드는 보호하고, 상품 교체 시 원래 적립 시각도 보존한다. [시간·쓰기 잠금](../../app/app.py) · [정정과 감사 기록](../../app/staff_admin.py)
3. 같은 초에 취소·재적립하거나 상품을 교체해 개수가 그대로인 경우에도 과거 조회로 새 작업을 승인하지 않아야 한다. 보유 수와 취소·정정 감사 건수를 조합한 카드 버전을 조회와 쓰기에서 비교한다. 고유 요청 ID로 응답 유실 뒤 재전송도 구분한다. [API 및 카드 상태](../../app/staff_admin.py)
4. 기존 카드는 정정 이관 없이 조회할 수 있다. Linux 합성 환경에서 `python deploy/linux/demo.py migrate-corrections --state-dir <합성-상태-폴더> --config <행사-설정> --origin https://demo.example.invalid`로 이관한다. 이 명령은 이미 준비된 DB의 서명과 QR 집합을 확인하며 합성 검증용 `.invalid` 호스트만 허용한다. SQLite 백업에 감사 행과 트리거도 포함된다. [스키마](../../app/correction_schema.sql) · [이관 검사](../../app/correction_schema.py) · [Linux 이관](../../deploy/linux/demo.py) · [암호화 백업](../../deploy/linux/backup.py)
5. 직원 화면은 서버에서 받은 카드별 권한을 표시한다. 관리자는 사유와 전후 상태를 검토하고 최종 확인하며, 성공 후 카드를 다시 조회한다. 화면이 오래됐거나 중복 전송돼도 서버에서 다시 검사한다. [화면](../../app/templates/admin.html) · [동작](../../app/static/admin.js) · [화면 테스트](../../app/tests/admin-flow.test.cjs)

## 검증 근거와 범위

[API·시간 경계](../../app/tests/test_admin.py)에서는 합성 카드·두 역할·독립 SQLite 연결을 사용한다. 가상 시계와 실제 쓰기 잠금으로 정각을 넘기는 요청을 만들고, 감사 삽입만 실패하도록 한 연결에서 스탬프 변경과 감사가 함께 롤백되는지 확인한다. [자격 분리](../../app/tests/test_manager_credentials.py), [양방향 이관과 실패 복구](../../tests/test_contact_privacy.py), [암호화 복원](../../tests/test_linux_demo_backup.py), [Windows 복원 검사](../../tests/test_windows_ops.py)도 독립된 임시 DB·파일만 사용한다.

### 이번 작업에서 직접 실행한 검사

| 범위 | 환경과 방법 | 관측 결과 |
|---|---|---|
| Python 전체 회귀 | Ubuntu 24.04.5, Python 3.12.3, SQLite 3.51.3. 외부 네트워크를 끈 컨테이너에서 로컬 HTTP·HTTPS 검사를 활성화 | **305건 통과**, 실패·건너뜀 0건. 202.89초. |
| JavaScript 전체 회귀 | 같은 Ubuntu 환경, Node 18.19.1 | **80건 통과**, 실패·건너뜀 0건. 이 중 관리자 화면은 기존 7건과 신규 7건을 포함한다. |
| 이관·백업·복원 | macOS, Python 3.13.5, SQLite 3.45.3. 합성 DB로 연락처 이관, Linux 기동·암호화 백업, Windows용 복원 검사 코드 실행 | 관련 57건 통과. 암호화 보관본을 별도 위치에 복원한 뒤 감사 행 14개 필드와 스탬프가 일치했다. 실제 Windows 서비스는 가동하지 않았다. |
| 직원·관리자 브라우저 통합 | Playwright와 데스크톱 Chrome 158. 앱과 브라우저의 시각을 2월 12일로 맞추고 로컬 Flask와 임시 SQLite에 연결 | 직원 변경 버튼 0개. 관리자 사유 입력·전후 확인까지 정정 POST 0건, 최종 확인 후 200 응답 1건. 재조회에서 상품이 교체되고 1/10개가 유지됐다. DB에서 원래 적립 시각, 관리자 감사 1행, 일반 취소 이력 0행을 확인했다. |
| 좁은 화면 | 데스크톱 Chromium 390×844, 합성 API 응답 | 마감 안내·필수 사유·단일 전송·재조회 표시를 확인했다. 검사 중 가로 넘침과 페이지 오류는 없었다. 휴대폰 실기기 검수는 남았다. |

전체 회귀에 사용한 명령은 다음과 같다. 추가로 실행한 부분 검사 건수를 위 전체 수치에 다시 더하지 않는다.

```sh
MAISON_HTTPS_TEST=1 MAISON_HTTP_TESTS=1 python -B -m pytest -q -p no:cacheprovider -ra --tb=short app/tests tests
node --test app/tests/*.test.cjs
```

첫 브라우저 통합 시도에서는 서버의 가상 시각만 미래로 이동시켜 기존 로그인 만료 타이머가 즉시 동작했다. 브라우저 시각도 같은 시점에 맞춰 위 시나리오를 재실행했다. 행사 기간과 정정 권한은 서버의 행사 설정·시각으로 판단한다.

소유자 직접 재현 기록은 본인이 확인한 뒤 날짜·실행 범위·자기 설명을 추가한다. 실제 매장 관리자 기기, 운영 자격 발급, 실데이터 이관과 PROD 배포는 이 검증에 포함되지 않는다. 3월 31일 종료·파기와 [PROD 개인 복구 링크 정책](../decisions/ADR-010-prod-card-recovery.md)의 구현은 별도 작업이다.
