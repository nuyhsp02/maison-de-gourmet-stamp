## 문제와 선택

DEMO는 시연 입장 비밀번호와 허용된 합성 프로필을 사용하며 개인 복구 링크도 제공한다. 이를 그대로 공개하면 매장 고객이 QR마다 공용 계정을 필요로 하고, 설정 하나를 잘못 선택했을 때 DEMO의 DB·키·이미지가 운영에 들어갈 수 있다. 사이트에 도착한 고객이 무엇을 볼 수 있는지와, 개인정보를 새로 저장할 수 있는지를 독립적으로 검사하도록 했다.

## 검증 기록

[가입·복구 시험](../../tests/test_prod_enrollment.py), [이관 차단·QR 시험](../../tests/test_prod_runtime.py), [암호화 복원 시험](../../tests/test_prod_backup.py), [패키지·공개 HTTPS 시험](../../tests/test_prod_public.py)을 같은 작업 트리에서 실행했다. 실서비스 주소와 키는 사용하지 않았다.

Nginx 시험은 상위에 실제 Basic 인증을 건 제어용 가상 서버부터 확인했다. 자격 없이 제어 서버를 방문하면 401과 Basic 챌린지가 왔다. 같은 상위 설정 아래 PROD 가상 호스트에서 고객 페이지와 상품 QR은 200, 가입은 403, 직원 전용 조회는 앱의 401이었으며 PROD 응답에는 Basic 챌린지가 없었다. 제어 서버가 처음에는 OS의 기본 로그에 쓰려 해 권한 검사에 실패했다. 시험용 부모 로그를 끄고 PROD 가상 호스트의 익명 로그를 별도 파일에서 확인했다. [기존 DEMO 통합 시험](../../tests/test_linux_proxy.py)

### 최종 회귀에서 확인한 수치

외부 네트워크와 호스트 파일 공유를 끈 Ubuntu 24.04.5에서 Python 3.12.3, SQLite 3.51.3, Node.js 18.19.1, Nginx 1.24.0을 사용했다. 서버 시계는 변경하지 않았다.

| 이번 전체 실행 | 통과 | 실패 | 건너뜀 |
|---|---:|---:|---:|
| Python 앱·운영 | 350 | 0 | 0 |
| Python 공개 검수 도구 | 51 | 0 | 0 |
| JavaScript | 92 | 0 | 0 |

```sh
MAISON_HTTPS_TEST=1 MAISON_HTTP_TESTS=1 python -B -m pytest -q -p no:cacheprovider -ra --tb=short --junitxml=/tmp/regression.xml app/tests tests
node --test app/tests/*.test.cjs
```

Python 전체 401건은 296.63초, JavaScript 92건은 2.25초에 통과했다. 이전 실행의 342·90건은 위 수치에 합산하지 않았다. 일반 입장과 상품별 합성 QR 11개의 SVG는 독립 판독기 jsQR로 다시 읽어 원래 URL과 11/11 일치를 확인했다. 소스 체크아웃에서 분리한 시험용 패키지에서도 합성 DB 준비, 두 역할 발급, 기동 검사, 암호화 백업·격리 복원, 재발급 후 검사가 성공했다.

## 남은 운영 인수와 학습 질문

운영 서버의 TLS·DNS, 개인정보 처리의 법적 근거와 최종 안내, 실제 상품 자산 권리, 승인된 고유 키와 운영자 인계, 3월 말 파기와 백업 보유기간은 출시 전 확인 대상이다. 로컬에서 승인 경로를 연 사례는 시험용 데이터에 한정한다.

1. 같은 프록시에서 고객 화면 200, 가입 403, 직원 조회 401을 각각 재현하고 응답의 `code`와 `WWW-Authenticate`를 비교한다. 결정 주체가 Nginx인지 앱인지 설명한다.
2. 합성 정책을 고정한 뒤 이름·전화번호로 가입하고 정책 파일을 철회한다. 신규 가입 거부와 기존 카드 찾기 성공이 함께 성립하는 이유를 설명한다.
3. 행사 설정·상품 QR·프로필 키·수신 공개키를 하나씩 바꾼 격리 후보의 기동이 중단되는지 확인한다. DB와 키가 모두 과거 사본이면 최신 상태 여부를 무엇으로 판별할지 설명한다.
4. 가짜 카드의 암호문을 지정 운영자로 조회하고 감사 결과를 대조한다. 서버 백업만 있으면 무엇을 복구할 수 있는지, 어떤 개인키를 별도로 인수해야 하는지 설명한다.

개발자 직접 재현 날짜, 확인한 코드, 자신의 설명은 직접 수행한 뒤 기록한다.
