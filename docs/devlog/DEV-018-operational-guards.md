# DEV-018 · 행사 자동 전환 및 관리자 자격 폐기 안정화

- 기록일 — 2026-11-26 KST. 기준은 `feature/contact-privacy-admin`의 `19b08b4`와 그 위에 있던 미커밋 변경 23개다.
- 사용자가 최종 검토의 세 항목과 운영 조건을 승인했다. AI 도구가 코드·문서를 변경하고 합성 환경에서 검증했다. 소유자 직접 재현과 매장 인수는 별도다.
- [관리자 예외 정정 정책](../decisions/ADR-009-stamp-corrections.md)과 [기존 권한·트랜잭션 검증](DEV-017-stamp-corrections.md)을 이어간다.

## 최종 검토에서 발견한 문제

1. 이관 명령의 합성용 호스트 이름과 실제로 쓰기를 여는 DB 경로는 독립된 입력이었다. DB 서명이 유효해도 그 파일이 이번 연습을 위해 만든 대상이라는 증거는 부족했다.
2. 2월 1일과 3월 1일에 화면을 계속 열어 둔 검토에서 자정의 재조회는 0건이었다. 서버는 마감 후 변경을 거부했지만 이전 버튼과 확인창이 남아 최종 확인이 유효한 것처럼 보였다.
3. 기존 관리자 세션은 계정과 검증 파일에 묶여 있었다. 검증 파일을 과거 상태로 되돌리면 같은 프로세스의 이전 미만료 세션이 다시 인정될 조건이 남아 있었다. 운영 고객 피해가 발생했다는 기록은 없다.

## 구현과 선택 근거

**이관 대상을 먼저 식별한다.** 별도로 새로 준비한 비공개 합성 원본과 대상에만 이관을 허용한다. 준비할 때 지정한 목적·행사·파일 식별 정보와 실행할 때의 절대 경로·실제 파일·스키마·행사 서명·상품·QR 집합·기존 데이터 존재 여부를 대조한다. 읽기 전용 사전 검사 후 대상의 SQLite 쓰기 잠금 안에서 다시 확인한다. 이관 명령에 기존 실서비스 DB를 등록하는 경로는 두지 않았다. 데이터가 있는 DB에서의 비파괴 DDL 호환성은 별도의 합성 트랜잭션 시험으로 확인한다. [이관 식별](../../deploy/linux/migration_target.py) · [준비와 이관](../../deploy/linux/demo.py) · [사용 절차](../CONTACT_PRIVACY.md)

**마감 버튼을 누를 수 있는지는 서버가 정한다.** 세션 응답은 서버의 현재 시각·현재 기간·다음 권한 변경 시각을 함께 전달한다. 브라우저는 두 서버 시각의 차이를 이용해 재조회를 예약한다. 사용자가 노트북의 달력이나 시간대를 바꿔도 그것으로 권한을 열지 않는다. 경계에서는 확인창과 오래된 카드 버전을 먼저 폐기한다. 서버가 반환한 기간과 새 카드 조회 결과가 맞을 때 해당 버튼을 다시 표시한다. 탭 복귀·포커스·주기 확인으로 지연된 타이머를 보완한다. 권한을 확인할 수 없는 동안은 변경을 잠근다. 실제 정정 API의 쓰기 잠금 뒤 권한·시각 확인은 계속 적용된다. [서버 판정](../../app/app.py) · [세션 응답](../../app/staff_admin.py) · [화면 동작](../../app/static/admin.js)

**관리자 파일과 DB가 같은 발급 회차인지 검사한다.** 현재 설계는 DB당 한 명의 지정 관리자를 지원한다. 새로 발급한 검증값과 계정에서 만든 지문을 기존 메타데이터에 기록한다. 새 salt가 들어간 검증값이 발급 회차를 구분하므로 별도의 숫자 세대 테이블을 만들지 않았다. 자격 교체·폐기 시 관리자 세션을 제거한다. 직원 세션과 고객 카드는 유지한다. DB와 파일 중 한쪽만 교체된 경우 관리자 로그인을 닫고 운영자가 재발급하도록 한다. 관리자가 여러 명인 매장은 개인별 자격·개별 폐기와 감사 식별이 갖춰진 뒤 확장해야 한다. [관리자 자격·세션](../../app/staff_admin.py) · [운영 명령](../../app/manage.py)

**복원 후보에서 먼저 관리자 권한을 해제한다.** 백업을 만들 때 원본 관리자 상태는 건드리지 않는다. 공식 Linux 복원과 Windows용 복원 후보 처리에서는 복사된 DB의 관리자 자격과 세션을 폐기한다. 프로세스 재시작도 옛 쿠키를 무효화한다. 매장 담당자는 새 관리자 비밀번호를 발급하고 두 역할을 각각 확인한다. DB와 파일을 운영 절차 밖에서 함께 과거 바이트로 교체하면 DB 내부 지문만으로 과거 시점임을 독립적으로 판별할 수 없다. 복구 승인과 별도 보관 기록이 필요하다. [Linux 복원](../../deploy/linux/backup.py) · [Windows 후보 복원](../../scripts/ops.py)

## 현장에서 사용할 문서

[직원 매뉴얼](../STAFF_GUIDE.md)은 마감 이후 직원이 오류를 어디로 전달하는지, 화면이 잠겼을 때 무엇을 확인하는지 설명한다. [백업 체크리스트](../DEMO_BACKUP.md)는 정정 감사 건수와 14필드 지문, 행사·상품 QR 매핑, 이전 쿠키 거부와 두 역할의 재로그인까지 포함한다. 이 지문은 신뢰하는 백업 회차에서 복원된 감사 행이 같은지 확인하는 데 사용한다. 예전 백업에 지문이 없으면 비교 증거를 따로 확인한다.

## 검증 기록

직전 DEV-017의 Python 305건과 JavaScript 80건은 이전 실행 결과다. 아래 집중 검사는 같은 사례가 전체 회귀에도 포함될 수 있어 합산하지 않는다.

| 이번 집중 검사 | 방법과 결과 |
|---|---|
| 합성 이관 대상 | `python -B -m pytest -q -p no:cacheprovider tests/test_linux_migration_target.py`에서 24건 통과. 잘못된 원본·대상, 행사·서명·상품·QR·스키마, 데이터가 든 대상, 심볼릭 링크·하드 링크·서비스 경로, 목적 누락과 사전 검사 이후의 변경을 다뤘다. |
| P2 권한·복원 | 관리자 자격, 공식 복원 후보와 잠금 경합을 선택 실행해 16건 통과. 비밀번호 교체·폐기, 옛 검증 파일 복사, 복원 후보의 재발급, 검증 파일 교체 후 DB 커밋 전 장애를 포함한다. |
| 서버 시각과 관리자 화면 | 로그인·세션 응답의 경계/초 미만 시각/초안 시험 5건 통과. `node --test app/tests/admin-flow.test.cjs`는 기존 14건과 신규 10건, 총 24건 통과. 가상 시계와 지연 응답을 이용해 열린 확인창·구 revision 무효화, 백그라운드 복귀와 재연결을 확인했다. |
| 실제 브라우저의 화면 | 데스크톱 Chrome 158, 390×844 화면, 합성 HTTPS 응답. 브라우저의 달력을 2037년, 서버를 2027년으로 설정했다. 세 경우(2월 직원·관리자, 3월 관리자) 모두 확인창 자동 종료, 카드 재조회, 자동 쓰기 요청 0건을 확인했다. 휴대폰 실기기·운영 서버는 사용하지 않았다. |

복원 후 감사 지문을 계산하는 순서를 처음에는 WAL 전환 뒤에 두었다. macOS에서 읽기 전용 연결을 닫은 뒤에도 복원 디렉터리에 WAL·SHM 파일이 남아 기존 두 파일 인수 조건이 실패했다. 원본과 감사 행은 보존됐다. 복원 후보에서 관리자 폐기를 커밋한 직후 지문을 계산하고 마지막에 WAL로 전환하도록 순서를 수정했다. 기존 검사를 그대로 다시 실행해 `tests/test_linux_demo_backup.py` 11건이 통과했다. 수정 전 시작했던 격리 회귀는 중단하고 최종 소스로 전체 결과를 집계했다.

최종 소스는 네트워크를 차단한 Ubuntu 24.04.5 LTS에서 Python 3.12.3, SQLite 3.51.3, Node.js 18.19.1로 한 번 전체 실행했다. 합성 HTTP·HTTPS 통합 시험도 활성화했다. Python 결과는 JUnit 기록의 테스트 모듈 기준으로 구분했다.

| 전체 회귀 | 통과 | 실패 | 건너뜀 |
|---|---:|---:|---:|
| Python 앱·운영 도구 (SQLite 경합·백업 복원 포함) | 291 | 0 | 0 |
| Python 공개 검수 도구 | 51 | 0 | 0 |
| JavaScript | 90 | 0 | 0 |

```sh
MAISON_HTTPS_TEST=1 MAISON_HTTP_TESTS=1 python -B -m pytest -q -p no:cacheprovider -ra --tb=short --junitxml=/tmp/regression.xml app/tests tests
node --test app/tests/*.test.cjs
```

Python 전체 342건은 250.49초, JavaScript 90건은 1.79초에 통과했다. Windows용 복원 절차의 자동 검사는 이 Linux 환경에서 실행했다. Windows 기기에서 복원한 결과는 별도로 확인해야 한다.
