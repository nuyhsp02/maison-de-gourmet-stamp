# DEV-012 · 연락처 암호화와 직원·운영자 권한 분리

- 기록 유형·기록일 — 구현·오류 수정·격리 검증 회고, 2026-11-25
- 작업일·기준 — 2026-11-25, `cf6b88f → aaccb50` (`feature/contact-privacy-admin`)
- 상태·주체 — 사용자가 전체 번호 보호·직원 마스킹·운영자 한 건 조회를 요구했습니다. Codex가 구현하고 임시 DB와 키로 시험했습니다. 소유자의 직접 구현·재현·이해 범위는 미확인입니다.

## 1. 문제와 예상 동작

카드 검색과 중복 확인에는 번호의 HMAC이 충분했지만, 매장은 상품 관련 연락을 위해 권한 있는 사람이 고객의 번호를 확인할 수 있기를 원했습니다. ‘미수령 상품에 대한 연락’은 구현 이후 11/25 지시에서 구체화한 목적입니다. 직원은 카드 검색·취소를 계속할 수 있어야 하고, 전체 번호를 읽는 권한은 분리해야 했습니다. 기존 고객의 정보를 추정해 채우거나 실데이터로 시험할 수 없었습니다.

## 2. 관측과 원인

기존 프로필에는 복호화할 전화번호가 없어 과거 카드의 끝자리도 복원할 수 없었습니다. 또 기동 검사가 원래 스키마와 QR 집합을 확인하기 때문에 새 테이블만 추가한 DB는 구버전에서 열리지 않았습니다. 이전 비밀번호 변경 명령과 고객·직원 세션 분리는 이미 있었습니다. 이 커밋은 직원 인증의 최초 도입보다 뒤에 온 강화 작업입니다. [PR2 직원 인증과 취소 감사](../PR2_STAFF_ADMIN.md)

## 3. 해결 또는 조사 과정

1. 마스크용 끝자리만 두는 안과 연락 가능한 암호문을 추가하는 안을 대조했습니다. 기존 HMAC 검색을 유지하고 새로 허용한 합성 가입에서만 연락처를 함께 저장했습니다. 기존 카드 찾기·직원 검색 시 번호는 자동 저장하지 않았습니다.
2. 서버에는 수신 공개키만 두고 지정 Mac의 개인키로 한 건씩 엽니다. 직원 화면에는 마스크만 반환합니다. 운영자 조회는 사유에 해당하는 용도와 대상을 확인하고, 감사 저장 성공 후 암호문을 전달합니다. [선택 이유와 위험](../decisions/ADR-007-contact-privacy.md)
3. 기존 직원 비밀번호 명령을 재사용해 15자 이상·흔한 값 거부·숨김 확인 입력을 적용했습니다. 첫 Ubuntu 전체 실행에서 Python 시험 3건이 실패했습니다. 마스킹 응답 필드의 기대값, 외래키가 있는 손상 복원 시험의 준비, 기동 시 읽기 전용 검사에 맞춰 시험을 바로잡고 전체를 재실행했습니다.

## 6. 미검증 사항과 후속 확인

구버전은 이관 후 DB를 거부했습니다. 새 적립·연락처가 생긴 뒤에는 최신 DB를 보존하는 호환 코드가 필요합니다. 지정 Mac 분실 시 복구 책임과 운영 키 보관, 실제 고객 가입의 법적 처리 근거, 백업 만료는 출시 전 과제입니다. 이후 사용자가 결정한 단일 안내 체크박스와 고객 접근·파기 기준을 이 커밋이 구현했다는 검증은 없습니다. [개인정보 운영과 롤백](../CONTACT_PRIVACY.md)
