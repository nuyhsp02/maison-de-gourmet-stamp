# DEV-015 · 공개용 Git 이력 정비 및 이미지 사용 권한 확인

- 기록일 2026-11-25. 비공개 개발 브랜치를 포트폴리오로 공개하기 전 실시한 로컬 검수다.
- 기준 브랜치는 `feature/contact-privacy-admin`이다. 공개 main은 `cceed35`, 기존 Draft PR #4는 `ed9912a`, 이번에 만든 후보는 `bbfb27b`다.
- Git 객체 대조와 시험은 Codex가 실행했다. 카페 그림의 사용 목적과 허가 범위는 사용자가 확인했다.

## 1. 문제와 예상 동작

첫 정비에서는 미공개 8개 커밋의 작성자·커미터 이메일을 GitHub noreply로 바꿨다. 파일 내용은 그대로 보존했으므로 현재 문서를 편집해도 과거 커밋에서 내부 설계 페이지 주소를 읽을 수 있었다. 이번에는 이미 공개한 22개 커밋을 고정하고 그 뒤의 문서 이력만 고치도록 사용자가 승인했다. [첫 정비 당시 기록](DEV-014-public-history-review.md)

## 2. 관측과 원인

PR 1·2·3 설명 문서에 내부 링크가 2개씩 있었다. 네 페이지의 주소가 세 문서의 네 파일 버전에 걸쳐 남아 있었다. PR 3 문서의 앞뒤 두 버전은 별개의 파일 객체였다. 해당 브랜치가 GitHub로 전송되면 독자가 과거 버전을 열 수 있으므로 마지막 문서에서만 주소를 지우는 방법은 이 요구를 충족하지 못했다.

## 3. 해결 또는 조사 과정

1. 작업 폴더 밖에 새 비공개 백업을 만들었다. 전체 Git 참조와 HEAD를 포함한 bundle, 원격 설정, 브랜치·부모 목록, 스테이징 상태, 미커밋 패치, 이미지 SHA-256, 추적·신규 작업 파일 원본을 보관했다. bundle의 참조와 SHA-256을 검증하고 추적 파일 10개를 패치로 복원해 바이트 단위로 확인했다. 신규 파일 8개도 아카이브와 일치했다.
2. 각 커밋에서 당시 존재한 문서의 링크 문장 한 줄씩을 교체했다. PR 3의 두 파일 버전을 구분하고, 대체한 상대 링크의 대상이 **그 시점의 커밋에도** 있는지 확인했다. 커밋별 전체 경로·파일 모드, 다른 파일 내용, 메시지, 작성자·커미터 정보와 시각을 비교하고 부모 대응을 검사했다.
3. 기존 인덱스 복사본에 두 트리 병합을 시도하자 Git이 수정된 PR 문서 보호를 위해 중단했다. 그때 작업 파일과 브랜치는 그대로였다. 원래 인덱스에 스테이징된 변경이 없음을 재확인하고 별도 인덱스에 새 트리를 구성했다. 전체 조상 검사 후 대상 참조와 인덱스만 전환했다. 작업 파일 3개의 기존 편집은 새 HEAD와 바이트가 같아져 미스테이징 목록에서 빠졌다.
4. 사용자가 카페 그림 10종의 **비상업적 포트폴리오 사용 허가를 받았음**을 확인했다. 원본의 바이트·상품 ID·경로를 대조했고 적용 범위를 문서화했다. [자산 출처·허가 범위·원본 지문](../ASSET_ATTRIBUTION.md)

## 6. 미검증 사항과 후속 확인

검사한 브랜치 이력은 사용자가 확인한 비상업적 포트폴리오 목적의 공개 후보로 사용할 수 있다. 전체 자료를 게시하려면 작업 트리에 있는 자산 안내, 포트폴리오 문서와 검수 도구를 먼저 검토·커밋한 뒤 최종 SHA에서 다시 검사하고 공개 승인을 받아야 한다. 다른 브랜치나 태그를 함께 전송하면 옛 이력이 포함될 수 있다. [단일 브랜치 공개 절차](../GIT_GUIDE.md#공개-후보와-비공개-보관-이력을-함께-쓰는-경우)

허가의 근거는 사용자의 확인이다. 상업적 이용 및 제3자 자유 재사용에 대한 별도 허가는 확인되지 않았으며 프로젝트 전체 라이선스는 미지정이다. PROD 운영 승인과 실고객 가입은 별도 절차다.
