# PROD 백업 만료와 복원 인수

운영자는 행사 DB와 분리한 보관 호스트에서 파기 원장, 승인본, 삭제 영수증을 관리한다. **일상 백업의 보유 일수는 미승인**이다. 기준 일수와 승인 자료의 지문을 원장에 등록해야 백업 복원 훈련을 진행할 수 있다. 2027-03-31 00:00 KST에는 일상 보유 일수가 남아 있는 사본도 만료된다. 일상 보유 일수가 미확정이어도 행사 종료 파기 범위, 복원 훈련, 사본 목록이 승인된 경우 기등록 사본의 종료 파기를 수행한다. 감사 자료의 파기 범위 승인, 복원 훈련 및 전체 보관처 조사가 부족하면 종료 상태를 유지하고 파기 완료 확인을 보류한다. [설계 결정](decisions/ADR-012-prod-privacy-erasure.md)

## 보관 목록과 준비

| 분류 | 찾을 대상 |
|---|---|
| `archive`, `local`, `external` | CMS 원본, 호스트·운영자 장치·외부 보관소의 별도 사본 |
| `restore`, `quarantine`, `previous` | 평상시 복원 후보, 종료 후 재파기 격리 후보, 교체 전 DB·키 사본 |
| `temporary` | 백업 중인 SQLite 스냅샷, ZIP, 암호화 중간 파일, 비정상 종료가 남긴 작업 디렉터리 |
| `snapshot` | 볼륨·VM 스냅샷, 백업 장치 이력, 오브젝트 버전과 휴지통 등 제공자 관리 사본 |

1. 보관 책임자가 호스트와 서비스 제공자별 실제 사본 목록 및 증거를 검토한다. 자동 백업, VM 스냅샷, 운영자 Mac 백업, 동기화 폴더와 저장소 버전 관리도 확인한다. 각 사본을 독립 원장에 등록하고 보관처 인벤토리를 승인한다. 한 장치에서 다른 장치로 임의 복사하면 도구가 이를 자동으로 찾아 주지 못한다.
2. POSIX 볼륨마다 서비스 계정 소유 0700의 전용 디렉터리를 할당한다. 신규 독립 32자리 소문자 16진 볼륨 ID를 발급한다. 일반 보관 디렉터리에는 이 ID를 담은 0600 파일 `.maison-custody-volume`을 둔다. 서비스 상태 루트에는 표식 파일을 추가할 필요가 없다. 그 루트는 등록된 PROD DB의 인스턴스 식별을 검증한다. 같은 볼륨을 다른 호스트에서 마운트해도 같은 ID가 필요하다.
3. 별도 경로에 `format: prod-backup-roots-v1`, `event_id`, `instance_id`, `volumes`, `manual_kinds` 필드를 가진 JSON을 만든다. 각 `volumes` 항목은 절대 경로 `path`, `volume_id`, 해당 볼륨의 `kinds` 배열과 불리언 `service`를 가진다. 서비스 상태 루트에는 `service: true`, `kinds: ["temporary"]`만 허용한다. CMS 목적지에는 `archive`와 `temporary`, 복원 루트에는 `restore`와 `quarantine`이 필요하다. 제공자 버전이나 스냅샷을 사용하는 종류는 `manual_kinds`에 포함한다. 볼륨 경로가 겹치면 등록이 실패한다.
4. 승인한 호스트별 파일을 `MAISON_PROD_BACKUP_ROOTS`, 별도 기록한 그 바이트의 SHA-256을 `MAISON_PROD_BACKUP_ROOTS_SHA256`으로 지정한다. 서비스와 복원 장치에는 [외부 원장 접속 정보](../deploy/linux/prod_authority.py)도 제공한다. 복원 호스트의 정책에는 자체 경로 매핑으로 동일한 아카이브 볼륨 ID와 별도 복원 볼륨 ID를 기록한다. 보관 원장의 인벤토리 승인 자료가 어떤 호스트별 지문, 어떤 제공자 계정·사본 집합에 해당하는지 독립적으로 관리한다.
5. 원장·증거 경로와 사본 디렉터리를 분리하고 외부 삭제 증거는 독립 관리자가 보관한다. 모든 등록 볼륨의 소유권, 쓰기 권한, 실제 파일 잠금이 생성 호스트와 만료 호스트 사이에서도 동작하는지 운영 인수에서 시험한다. 호스트간 디렉터리 잠금을 보장하지 않는 파일 공유, 공급자 계정 미확인, 등록되지 않은 수동 사본은 출시 차단 항목이다.

## 복원과 만료 명령

[PROD 백업 도구](../deploy/linux/prod_backup.py)는 암호화·복원을 시작하기 전에 외부 원장에 목적지와 임시 파일 위치를 예약한다. 원장에는 고객 식별정보, 개인 경로, DB 내용이 들어가지 않는다. 명령 출력에는 암호문 지문과 재파기 여부만 남기고, 감사 행을 바탕으로 계산한 지문은 암호화한 백업 내부에 보관한다. 이전 형식의 결과를 평문 파일에 보관한 경우에는 이전 사본 인벤토리에 포함한다. 위치 ID는 볼륨 ID 32자리 뒤에 해당 볼륨 바로 아래 파일명의 UTF-8 SHA-256 앞 32자리를 연결한다. 평상시 보유기간이 지난 아카이브는 새 복원 후보를 만들 수 없다. 원장이나 보관 루트를 확인할 수 없으면 복호화를 시작하지 않는다.

종료 후에도 발견한 기존 자료를 조사해야 하면, 아직 등록되어 있고 삭제 확인 이력이 없는 아카이브만 오프라인 격리 대상으로 복호화한다. 암호문 지문·DB·키·감사를 검증하고 직원 자격을 폐기한 뒤 고객 행을 재파기한다. 폐쇄가 복원 도중 도달하면 동일한 처리를 수행한다. 부분 실패 시 새 후보를 제거하고 중단한다. 격리 후보를 파기한 결과로 서비스 원본 파기를 증명할 수 없다. 이미 삭제 영수증을 발급한 위치에서 재발견한 옛 사본은 재복원을 거부한다.

독립 보관 호스트에서 [만료 도구](../deploy/linux/prod_backup_custody.py)에 `--ledger`, `--config`, `--instance`, `--receipts`를 지정한다. 모든 보관 볼륨을 확인하고 배타 잠금을 획득한 뒤 전체 목록과 원장을 먼저 대조한다. 낯선 파일, 재발견된 사본, 하드링크·심볼릭 링크, 누락된 마운트는 먼저 조사한다. 재발견하면 기존 완료 상태를 취소하며, 보관 책임자가 실제 출처와 범위를 확인한 뒤 원장의 `discover`에 분류와 위치 ID를 전달한다. 발견한 파일을 임의로 지워 누락을 숨기지 않는다.

만료 도구는 승인된 기간이 지난 등록 사본을 제거하고 디렉터리를 동기화한 후 다시 열거한다. 서비스의 검증된 `instance`와 내부가 빈 접근 종료 표식은 만료 대상에서 제외한다. 각 사본의 존재 전후와 확인 시점, 불투명 위치 ID를 담은 영수증을 남기고 그 지문을 외부 원장에 연결한다. 정상 종료 때 이미 없어진 임시 파일은 사후 재열거로 부재를 확인한 사실만 기록한다. 종료 후에는 해당 종류의 대상이 모두 사라진 보관처에 전체 목록 재확인 영수증도 남긴다.

운영자가 공급자의 전 버전·휴지통·스냅샷을 읽을 수 있는 자격으로 별도로 열거하고, 만료 동작 후 삭제 요청 ID와 재조회 결과를 독립 보관한다. 원장의 `attest`에는 삭제가 확인된 객체와 증거 파일 지문을, `reconcile`에는 전체 종류별 재조사 증거 지문을 제공한다. 사용하지 않은 종류도 조사 근거가 필요하다. 마운트에서 파일 하나가 사라진 사실은 제공자 복사본이나 SSD·스냅샷의 물리적 소거를 증명하지 않는다. 장치 단위 암호화, 네이티브 버전 관리, 분리된 보조 사본의 삭제를 매장 보관 책임자가 별도로 인수해야 한다.

## 예약과 장애 처리

[보관 호스트 전용 서비스](../deploy/linux/maison-custody-expire.service)와 [예약 파일](../deploy/linux/maison-custody-expire.timer)은 KST 매일 자정, 행사 마감 정각, 시스템 부팅 후에 만료를 점검한다. 평상시 복원 허용 여부는 각 백업 생성 시점부터의 승인 일수로 계산한다. 실제 파일 삭제는 다음 예약 실행 시 이루어진다. 보관 호스트가 꺼져 있다면 정각의 물리적 삭제는 지연될 수 있다. 앱의 접근 차단은 계속 적용된다.

실제 사용 전 별도 계정으로 실행하는 서비스의 환경 파일에 `CUSTODY_LEDGER`, `CUSTODY_RECEIPTS`, `PROD_EVENT_CONFIG`, `PROD_INSTANCE_ID` 및 호스트별 보관 루트·승인 지문을 지정하고, systemd의 `ReadWritePaths` 및 `RequiresMountsFor`를 승인한 경로에만 추가한다. 마운트·감사가 준비되지 않으면 실행이 실패한다. 오류 시 재시도와 담당자 알림, 독립 호스트 시간 동기화, 장치 복구와 원장 이력 연속성은 운영 인수 사항이다. 이번 작업은 합성 사본만 대상으로 삼았다.
