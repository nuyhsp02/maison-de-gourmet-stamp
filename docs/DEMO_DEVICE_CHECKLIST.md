# 11월 25일 · 휴대폰 2대와 직원 기기 인수표

**목표**는 외부 HTTPS를 통해 발표자와 매장 담당자가 같은 합성 카드의 등록·복구·적립을 직접 확인하고, 직원이 해당 카드의 지급·취소 상태를 검수하는 것이다. 아래 칸은 현장 실측용이다. 사전 로컬 실행은 별도 기록에 있다. [Ubuntu 시험 로그](evidence/pr3-linux-tests.txt) · [기동 절차](PR3_LINUX_DEMO.md)

A (발표자 / OS·브라우저) ______　B (담당자 / OS·브라우저) ______　S (직원 기기 / 브라우저) ______

| 확인 | 담당·행동 | 통과 기준 |
|---|---|---|
| ☐ | 운영자 · 시작 전 커밋, DB 및 키 검사, 영속 디스크, 시각과 시연 기간, 서비스 상태, 서버 외 격리 복원을 확인한다. | SQLite 버전·기동 검사 통과, 두 서비스 active, 복원 후 원본과 상품·카드·적립·지급·취소 합계가 일치한다. |
| ☐ | A는 매장 Wi-Fi, B는 이동통신에서 전용 도메인을 연다. 로그인 전 고객·QR·직원·상태 경로 및 정적 파일을 확인한다. | 두 기기 모두 정상 인증서 체인·도메인을 확인한다. 게이트 미인증 요청은 401이며 앱·카드가 보이지 않는다. 8875는 외부에서 열리지 않는다. |
| ☐ | A·B·S가 각자 DEMO 입장 자격을 사용한다. S는 직원 로그인 전 상태로 통계·조회 접근을 확인한다. | 고객 화면은 열리며 직원 데이터는 로그인 전 401이다. 입장 자격을 주소에 넣지 않는다. |
| ☐ | 버전 전환 시 A·B·S의 기존 DEMO 탭과 인앱 브라우저를 닫고 쿠키를 유지한 채 다시 연다. A는 상품 QR에서 합성 이름·번호와 안내를 입력하고, 등록 정보 확인에서 수정한 뒤 [이대로 등록]을 누른다. | 입력 확인·수정 중 카드 증가 0장. 등록 후 1장, 스탬프 0개. 처음 스캔한 상품의 확인창이 다시 열린다. |
| ☐ | B에서 같은 합성 번호의 공백·하이픈 표현으로 등록을 시도하고, 다른 이름·같은 번호로도 확인한다. | 새 카드가 생기지 않는다. 일치하면 기존 찾기 화면에서 같은 카드로 복구되며, 불일치 시 정정 안내가 나온다. |
| ☐ | S는 직원 로그인 후 기준 건수를 확인한다. A에서 상품 QR을 열어 취소하고, 다시 열어 새로고침한 뒤 상품명을 확인하고 [적립하기]를 누른다. B는 동일 카드·상품으로 다시 확인한다. | 조회·미리보기·취소·새로고침 때 적립 POST와 스탬프 증가 모두 0건. 최종 확인 후 1개, 같은 상품 재방문 후에도 1개. 일반 입장 QR에는 상품 확인창이 없다. |
| ☐ | A에서 브라우저 쿠키를 지우고 재입장한다. 이름·번호로 복구한 뒤 A와 B의 스탬프판을 새로고침한다. | 두 기기와 직원 조회에 같은 도장 1개가 보인다. 다른 이름으로 찾으면 접근할 수 없다. |
| ☐ | S가 수령 전 해당 상품의 도장 1개를 취소하고 A와 B에서 새로고침한다. 운영자는 취소 감사 건수를 확인한다. | 양쪽 카드는 0개, 취소 감사 +1건. 고객·상품·원 적립·취소 시각과 직원 식별이 DB에 남는다. 현장 기록에는 건수만 적는다. |
| ☐ | A와 B에서 앱 카메라로 프레임 밖·두 코드·중앙 한 코드를 비춘다. 취소 후 같은 QR을 그대로 비추고, 잠시 치운 뒤 다시 비춘다. 기본 카메라에서 다른 브라우저가 열리면 이름·번호로 카드를 찾는다. | 중앙의 단일 상품에 기본 카메라와 같은 이름·두 버튼이 뜬다. 취소한 코드를 계속 비출 때 확인창이 반복되지 않는다. 카드 찾기나 판독만으로 적립되지 않으며 최종 확인 후 한 번만 반영된다. |
| ☐ | A·B에서 앞서 적립한 상품을 포함해 합성 상품 10종을 완성한다. 실물 지급을 대신하는 시연 확인 후 고객 화면에서 지급 완료하고, B에서도 상태를 확인한다. S가 지급된 카드에서 취소를 시도한다. | 10개, 지급 완료 1건, 중복 지급 없음. 이후 취소 불가. 직원 PIN 입력 단계는 없다. |
| ☐ | S가 로그아웃 후 통계 재접근, A가 고객 상태 재조회, 담당자가 S의 게이트 자격 회수 후 재접근을 각각 확인한다. | 직원 재로그인 요구, A의 카드 유지, 회수한 게이트 자격으로는 앱 전체가 401이다. |
| ☐ | 승인된 리허설 시간에 운영자가 서버를 재부팅한다. 두 서비스를 확인하고 A·B·S에서 다시 접속한다. | 수동 준비 없이 부팅, 같은 고객 카드·도장·기존 QR·지급·취소 이력 유지. 옛 직원 세션은 거부되고 다시 로그인된다. |
| ☐ | 운영자가 시연 후 새 백업을 수신지에서 검증하고 당일 기록·로그·주소창·쿠키 속성을 확인한다. | Cloud/프록시/앱 로그에 이름·전화번호·비밀번호·QR 토큰·쿠키 값이 보이지 않는다. 접근 로그에는 시각·상태·바이트만 있다. 고객·직원 쿠키에서 Secure/HttpOnly를 확인한다. |
| ☐ | 담당자가 외부 입장을 종료하고 증적을 정리한다. | 게이트 계정 회수 또는 입구 종료가 확인되고, 합성 건수·시각·성공/실패·다음 담당자만 보고한다. |

**중단 기준**은 인증 없이 앱이 열림, 인증서 경고, 데이터·키 불일치, 미리보기만으로 적립, 중복 지급, 개인정보 로그 노출 또는 복원 검증 실패다. 이때 외부 입구를 닫고 현재 DB와 키 쌍을 보존한다. 상태가 확인될 때까지 신규 준비나 공개 시연을 진행하지 않는다.
